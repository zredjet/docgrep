# docgrep

Word / Excel ファイルの中身を、コンソールから **厳密一致** で検索するツールです。
ヒットした箇所ごとに「ページ（推定）」「章番号＋見出し」「前後の文脈」を色付きで表示します。

Word の検索は「サーバ」で「サーバー」や半角の「ｻｰﾊﾞ」まで拾ってしまうことがあります。
docgrep は全角半角・ひらがなカタカナ・長音・Unicode 正規化・空白などの **表記ゆれを一切吸収しません**。
書いたとおりの文字列だけを探します。

- Windows 10/11、macOS（Apple Silicon / Intel）で動く単一の実行ファイルです
- Word・Excel・LibreOffice などの外部ソフトは不要です
- フォルダを指定すると、中のファイルを再帰的に検索します（複数ファイルを並列に処理します）

```
■ docs/仕様書.docx  4件  (ページ: Word保存時のレイアウト情報)
  p.12  3.2.1 システム構成
        …本システムではWebサーバとアプリケーションサーバを分離し…
  p.12  3.2.1 システム構成  [表2 3行1列]
        サーバ名↵役割
  p.15  3.4 運用  [脚注3]
        夜間バッチはサーバ停止時間帯を避けて実行する。
  --    [ヘッダー]
        社外秘 サーバ構成資料

■ 見積.xlsx  1件
  [内訳] C14
        サーバ保守費用（年額）
```

## インストール

### ビルド済みの実行ファイルを使う場合

`docgrep`（Windows では `docgrep.exe`）を、PATH の通ったフォルダに置くだけで使えます。
ほかにインストールするものはありません。

### ソースからビルドする場合

[Rust](https://www.rust-lang.org/ja/tools/install) 1.88 以降が必要です。

```sh
cargo install --path .
```

または `cargo build --release` でビルドし、`target/release/docgrep`（Windows では `docgrep.exe`）を
PATH の通ったフォルダにコピーしてください。

## 使い方

```
docgrep [OPTIONS] <PATTERN> [PATH]...
```

- `PATH` はファイルまたはフォルダです。複数指定でき、省略するとカレントフォルダを検索します。
- フォルダは再帰的に検索します。出力はファイル名の順に並びます。
- `-` で始まる語を探すときは `--` の後に書きます（例: `docgrep -- -foo .`）。

### 例

```sh
# 「サーバ」を含む箇所。「サーバー」「Webサーバ群」も部分一致でヒットする
docgrep サーバ 仕様書.docx

# 「サーバー」を除外する（正規表現の否定先読み）
docgrep -e 'サーバ(?!ー)' 仕様書.docx

# docs フォルダ以下の Word / Excel をまとめて検索し、ファイルごとの件数だけを表示
docgrep -c サーバ docs/

# 脚注・文末脚注とコメントだけを検索
docgrep --parts note,comment 要確認 docs/

# 段落全文を表示する
docgrep -P 障害 手順書.docx

# JSON Lines で出力して別のツールで加工する
docgrep --json サーバ docs/ > result.jsonl
```

### オプション

| オプション | 説明 | 既定 |
|---|---|---|
| `-i, --ignore-case` | 大文字小文字を区別しない。全角の「Ａ」と「ａ」は同一視するが、半角の「a」とは別。全角半角・かなカナは区別したまま | 区別する |
| `-e, --regex` | PATTERN を正規表現として扱う（[fancy-regex](https://docs.rs/fancy-regex) の構文。先読み・後読み可） | リテラル |
| `-C, --context <N>` | マッチの前後に表示する **文字数** | 30 |
| `-P, --paragraph` | 前後を切り詰めず、段落（Excel はセル）の全文を表示する | |
| `--parts <LIST>` | Word の検索対象をカンマ区切りで指定: `body`（本文）`table`（表）`textbox`（テキストボックス）`note`（脚注・文末脚注）`comment`（コメント）`header`（ヘッダー・フッター）`toc`（目次）`all` | all |
| `-l, --files-with-matches` | ヒットしたファイルのパスだけを表示する | |
| `-c, --count` | ヒットしたファイルごとに `パス:件数` を表示する | |
| `--json` | JSON Lines（1マッチ1行）で出力する。色なし | |
| `--color <WHEN>` | `auto` / `always` / `never`。auto は端末に出力していて `NO_COLOR` が未設定のときだけ色を付ける | auto |
| `--max-depth <N>` | フォルダ探索の深さの上限（1 = 指定したフォルダの直下だけ） | 無制限 |
| `-j, --threads <N>` | 並列数 | CPU 数 |
| `-h, --help` / `-V, --version` | ヘルプ / バージョン | |

`-l`・`-c`・`--json` は同時に指定できません。

grep に慣れている方は、次の違いに注意してください。
- `-e` はフラグで、後ろに PATTERN を取りません。
- `-C` は行数ではなく文字数です。
- `-P` は Perl 正規表現ではなく、段落全文を表示する指定です。

### 一致のしかた

- 本文と PATTERN を、正規化も空白の畳み込みもせずにそのまま比較します。
- 検索の単位は Word が段落、Excel がセルです。段落やセルをまたいでは一致しません。
- Word の段落内の改行は `\n` として含まれるので、正規表現の `\n` で一致させられます。表示では `↵` になります。
- 同じ段落に複数ヒットすると、左から重ならないように列挙します。表示範囲が重なる場合は1つにまとめ、ヒットした箇所をすべて強調します。

## 出力の見方

- **ファイル行** `■ パス  件数  (ページモード)`: ページモードは Word ファイルだけに付きます。
- **位置行（Word）** `ページ  章番号 見出し  [パート]`
  - ページ欄の意味:
    - `p.12`: Word が最後に保存したときのレイアウト情報に基づく推定ページです。
    - `p.12+`: レイアウト情報が無いファイル（Word 以外のツールで作ったものなど）で、明示的な改ページだけから数えた参考値です。「12 ページ目以降」の意味です。
    - `--`: ヘッダー・フッターなど、ページのない箇所です。
  - 見出し欄: 直前の見出しを、自動番号付きで表示します。最初の見出しより前は `(冒頭)` です。
  - パート欄: `[表2 3行1列]` `[テキストボックス]` `[目次]` `[脚注3]` `[文末脚注1]` `[コメント: 作成者]` `[ヘッダー]` `[フッター]`
  - 脚注・コメントは、本文で参照されている位置のページと見出しを表示します。
- **位置行（Excel）** `[シート名] セル番地`: 非表示のシートは `[シート名(非表示)]` です。
- **文脈行**: 切り詰めた側に `…` が付きます。タブは空白、改行は `↵` で表示します。
- **警告とエラー**: 標準エラー出力に `docgrep: 警告: パス: 理由` または `docgrep: エラー: パス: 理由` の形で出ます。
- **サマリ**: 通常表示のときだけ、最後に標準エラー出力へ `検索 12ファイル / ヒット 2ファイル 5件 / スキップ 1 / エラー 0` を出します。

### JSON Lines（`--json`）

1マッチにつき1行の JSON です。表示上のまとめは行いません。

| フィールド | 内容 |
|---|---|
| `file` | 表示と同じパス |
| `format` | `word` / `excel` |
| `part` | `body` `table` `textbox` `toc` `footnote` `endnote` `comment` `header` `footer` `cell` |
| `part_label` | 表示用ラベル（`表2 3行1列`、`脚注3` など）。本文とセルは null |
| `page` / `page_mode` | 推定ページと `rendered` / `explicit`。Excel・ヘッダー・フッターは null |
| `heading` | `{"level": 3, "number": "3.2.1", "text": "システム構成"}`。番号が無ければ number は null |
| `sheet` / `sheet_hidden` / `cell` | Excel のシート名・非表示かどうか・セル番地 |
| `before` / `match` / `after` | 文脈（`-C` に従う。`-P` のときは段落全体を分割）。改行などはそのまま |
| `offset` | 段落（セル）内でのマッチ開始位置（文字単位） |

## 終了コード

| コード | 意味 |
|---|---|
| 0 | 1件以上ヒットし、エラーなし |
| 1 | ヒットなし、エラーなし |
| 2 | エラーが1つ以上あった（ヒットの有無にかかわらず） |

警告（暗号化ファイル、未対応の形式、ワイルドカードに一致なし）は終了コードに影響しません。
壊れたファイルや読み取れないファイルがあっても、エラーを表示して次のファイルの検索を続けます。

## 対象ファイル

| 種別 | 拡張子 |
|---|---|
| Word | `.docx` `.docm` `.dotx` `.dotm` |
| Excel | `.xlsx` `.xlsm` `.xltx` `.xltm` `.xlsb` `.xls` `.ods` |

- 上記以外（`.doc` など）は、引数で直接指定したときだけ警告を出します。フォルダの探索中は黙ってスキップします。
- 次のファイルは常に黙ってスキップします。
  - Office のロックファイル（`~$` で始まる名前）
  - macOS が USB メモリやネットワーク共有に作る `._` で始まるファイル
- フォルダの探索中の扱い:
  - `.` で始まるフォルダ（`.git` など）の中は探しません。
  - シンボリックリンクは辿りません。
- パスワード付きのファイルは「暗号化または旧形式のため読めません」と警告してスキップします。
- Windows の cmd.exe や PowerShell ではワイルドカードが展開されないため、`*` `?` を含む引数は docgrep 自身が展開します。
  大文字小文字は区別しません。`[` `]` は文字どおりに扱います。

### 検索の対象になるもの

- **Word**:
  - 本文・表・テキストボックス・脚注・文末脚注・コメント・ヘッダー・フッター
  - 数式の文字、隠し文字
  - フィールドの表示結果（目次やハイパーリンクの表示文字列など）
- **Word で対象外のもの**:
  - 変更履歴で削除された文字
  - フィールドコード
  - ルビ（ふりがな）の文字
- **Excel**: すべてのワークシート（非表示シートも含む）のセルの値
  - 数式のセルは、保存時の計算結果を検索します。
  - 値の表記:
    - 数値: 表示形式を反映しません（`¥1,234` は `1234`、`1234.0` は `1234`）。
    - 日付: `2024-01-15`、時刻付きは `2024-01-15 10:30:00`。
    - 真偽値とエラー値: `TRUE` / `FALSE`、`#N/A` など。

## 既知の制約

- **ページは推定値です**。最後に Word で保存した環境のレイアウト情報に基づくため、フォントの違う環境や Word 以外のツールで保存したファイルではずれます。
  また物理ページ（先頭 = 1）なので、文書に印刷されているページ番号とは一致しないことがあります。
  レイアウト情報の無いファイル（`p.12+` 表示）では、自動改ページを数えられないため、実際より小さい値になります。
- **自動番号（章番号・箇条書き番号）の文字列は検索できません**（Word の検索と同じです）。見出し欄の表示にだけ使います。
- **Excel の表示形式（桁区切り・通貨・日付書式）は反映しません。数式の文字列そのものは検索しません。**
- **旧形式の `.doc` と、パスワード付きのファイルには対応していません。**
- **変更履歴は「変更後」の内容で検索します**（削除された文字は対象外）。変更履歴で段落記号が削除された段落は、つながずに別の段落のまま検索します。
- **図形内の文字は、Word のテキストボックスだけが対象です。** SmartArt やグラフの中の文字、Excel の図形・メモは対象外です。
- **Word の数式は、文字の部分だけをつなげて検索します。** 分数や根号などの構造は文字にならないため、部分一致でしか当たりません。
- **段落（セル）をまたぐ語はヒットしません。**

### Windows での注意

- 出力は UTF-8 です。コンソールへの表示は問題ありません。
  ただし Windows PowerShell 5.1 でパイプやリダイレクトに渡すと、文字化けすることがあります。
  その場合は、先に次のコマンドを実行してください。

  ```powershell
  [Console]::OutputEncoding = [System.Text.Encoding]::UTF8
  ```

- 古いコンソール（conhost）とフォントの組み合わせによっては、`■` `↵` `…` が正しく表示されないことがあります。
  Windows Terminal の利用をおすすめします。
- `■` `…` `↵` `①` などは、表示幅が環境によって 1 桁にも 2 桁にもなる文字です。そのため、見出しの切り詰め位置が少しずれることがあります。

## 開発

仕様は [docs/SPEC.md](docs/SPEC.md) にあります。

```sh
cargo build
cargo test
cargo clippy --all-targets -- -D warnings
cargo fmt
```

- テスト用の docx は `tests/common` の `DocxBuilder` で XML 断片から生成します。xlsx は rust_xlsxwriter で生成します。
- 表示はスナップショットテストで固定しています。表示を意図して変えたときは `INSTA_UPDATE=always cargo test`（または cargo-insta を入れて `cargo insta review`）で更新し、差分を確認してください。
